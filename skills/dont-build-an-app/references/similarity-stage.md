# 第一阶段：同类检索、使用价值与证据不足

## 创意指纹

用用户原话与必要归纳记录：

| 维度 | 权重 | 比较内容 |
|---|---:|---|
| 前提/问题 | 20 | 使用情境与要解决的问题 |
| 核心机制 | 25 | 具体怎样解决 |
| 交互/执行 | 20 | 步骤、反馈、主要体验 |
| 目标用户 | 10 | 谁使用；可以是用户本人 |
| 可见呈现 | 15 | 看见、听见或操纵的形式 |
| 结果/承诺 | 10 | 完成后可观察的变化 |

同时记录目的：自用、学习、对外服务或商业用途等，未知就保留未知。人群或细节缺失时可带着标明的假设搜索，不用连续澄清阻止首次检索。

## 检索范围

按产品形态选择当下可用的渠道，不对所有产品强制检索视频平台。至少尝试四种不同查询族：

1. 名称、原话与中英文近义描述。
2. 问题、人群与使用情境。
3. 核心机制、输入输出和交互形式。
4. 现有替代办法，如其他软件、人工、表格或通用 AI。
5. 产品渠道，如官网、应用商店、Product Hunt、扩展商店。
6. 开源与作者案例；内容创意再按相关性选视频/内容平台。

首轮以四个查询族、三类来源、六个相关且可核验候选作为覆盖目标。达不到就记录缺口，不凑无关结果，不把目标当成无限搜索配额。优先打开官网、仓库和作者原帖；摘要只用于发现候选，不能单独承担高度相似结论。

复用已有 `idea-similarity-check` 时借用六维比较与证据方法，本流程的使用价值、停止条件和授权规则以本文件为准。只有实际需要 OpenCLI 时才读取可用的 opencli-usage，发现其当前命令；不要假设每台机器都有相同 CLI、登录或工具。

## 相似度与证据分开

有依据的维度按 `0 / 0.25 / 0.5 / 0.75 / 1` 评估并乘权重相加，解释每项重合和差异。未知维度记为未知，关键维度未知时不强行给总分或作高相似判定。分数是结构化判断，不是客观抄袭率。

另行记录检索覆盖：查询族 25、来源类型 25、主要候选一手证据 25、日期/实际功能说明核对 15、中英文或目标市场语言 10；部分满足按实际程度说明。此指标只是本次检索的过程完成度，不是全网覆盖率，也不能替代候选关键维度的一手证据。

数值用于辅助比较：`≥80` 高度相似、`60–79` 中度、`35–59` 相邻、`<35` 低相似。关键比较无一手证据，或检索覆盖不足以支持结论时，优先标记疑似/待定，不借分数强行放行或否决。

## 先分清相似，再判断是否值得继续

| 情况 | 处理 |
|---|---|
| 证据充分的高相似、同一目标人群，但存在有意义的改善或具体自用目的 | 可以继续；写清使用收益，不改写为“低相似”或原创 |
| 高相似、同一人群，用户尚未说明用途或改善 | 先问决定性缺口，不把信息缺失等同于没有价值 |
| 高相似、同一人群，沟通后仍无有意义的改善或具体自用价值 | 建议停止当前版本，说明重合和理由 |
| 中度/相邻/低相似，关键比较有足够依据 | 说明可继续审查的理由并进入第二阶段，不保证原创或成功 |
| 工具失败、摘要不足、冷门主题缺少资料或关键维度不明 | 保持待定，按下面的补查流程处理 |

建议停止需要相似度与覆盖均足以支持判断（有评分时通常为相似度 ≥80、检索覆盖 ≥65），且核心机制、用户、体验和结果有直接证据。不能仅因实现技术相同、名字相似或“未必打得过竞品”停止。

自用也需要描述本人想完成的任务及取舍，但不必证明商业竞争力。学习或兴趣可以是用户明确选择的目的，不为它伪造市场需求。离线、免注册等只是可能有意义的差异；是否有用应依据该用户的情境，不自动视为卖点。

## 聊清想法后的正式建议

先完成必要检索和交流，了解用户的目的、使用情境与所主张的改善，再根据上述条件给正式建议；不在第一次澄清问题前草率盖章。

- 建议停止当前版本：固定说“我的建议是：别做了”，接一张掌心朝向画面、掌心中央写“别做了”的图片。
- 有依据建议继续：固定说“我的建议是：可以做”，接一张竖大拇指、手上方空位写“可以做”的图片。
- 图片之后用简短理由和必要来源解释结论。这张图直接生成，不询问生图许可。具体生成、展示与退路读 [verdict-images.md](verdict-images.md)；没有生图能力或用户要求纯文字时保留文字建议。

“可以做”是值得进入下一阶段设计讨论，不是商业成功或开发已获授权；接着说“接下来进入下一个阶段”，按原规则询问后续回复配图。“别做了”时停止自动进入第二阶段；用户可补充用途、调整设计，或明确要求保留未通过判断继续讨论。重构只重审受影响的指纹与结论，见 progress-and-resume。

证据不足时保留待定，不为了这两个视觉结果强行下结论。用户选择继续不自动把待定改成“可以做”；若另有充分的具体自用或改善依据，可以据此建议继续，并如实保留相似性证据缺口。

## 证据不足时补查

1. 说明目前能确认什么、缺什么、为什么缺；不把搜不到说成独特。
2. 询问是否使用本机其他已有工具扩大搜索。用户已明确授权同一范围时直接执行，不重复征求；未回答、预选项、沉默都不算同意。
3. 同意后做有边界的能力发现：当前可调用工具、相关 Skill、已配置 CLI 及必要的帮助/状态命令。优先已注册的能力和已知安装位置，不扫描全盘文件、私人资料或凭据寻找工具。
4. 选择能补当前缺口的少量渠道，用不同查询族补查，避免换工具却重复同一批结果。只处理本轮所需的公开检索信息；使用现有工具的同意不等于安装、修复、改配置或新增付费授权。
5. 本轮补查出现稳定结果、不再产生影响判断的新证据，或可用渠道均阻塞时停止。只有出现值得追查的新线索或用户要求时再扩展；不要为了声称“做到一切”无期限试工具。
6. 仍不足时记录实际渠道、结果和缺口，维持 `待定`。用户决定是否继续承担未知、补充材料或暂停；不是让用户凭感觉裁定原创性。

用户明确说“不补查，继续设计”时进入后续阶段，第一阶段仍待定。仅拒绝使用其他工具时，不自行推断继续或放弃。后续选择继续与补查授权分别记录；不能把其中一项当成另一项的授权。

网络工具不可用、未登录或补查失败，都不输出假检索结果。用户不授权或宿主无法执行时也适用待定流程。

## 记录与前台

后台记录日期、查询、渠道、候选链接、证据依据、相似与使用价值、缺口、补查授权/范围/结果，以及是否获准带着待定继续。记录“未查”和“查过但没找到”的区别。

正式结论轮采用 verdict-images 的顺序；其余前台按 conversation-style：短回应点名关键对象或证据缺口，再给能推进决定的相关问题。扩展搜索的授权问题单独处理；普通搜索记录留到用户追问、进度文档或最终设计再展开。
