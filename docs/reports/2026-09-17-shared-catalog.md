# 本机统一存档与同页切换

日期：2026-09-17。范围：同一操作系统账号下，多个安装目录、多个已接入 Agent 的网页存档汇总。没有新增模型、云端中转或付费依赖。原有兼容认证状态不变。

## 已实现

- 安装器、启动器和直接运行入口共用标准本地数据根目录，通常无需配置。显式 GALGAME_HOME / GALGAME_REGISTRY_DIR 仍可隔离环境。只登记显式启动并建立了网页存档的原任务，不扫描全量私人历史。
- 索引按适配器与任务 ID 共同标识，避免不同应用的同名任务 ID 覆盖。原子更新并对 Windows 短暂文件占用有限重试；损坏的单条索引不会让整个列表失效。旧索引与新版登记去重，删除标记防止旧条目重新出现。
- 存档列表显示 Agent、名称、更新时间、连接状态；可按 Agent 筛选、刷新。断线条目保留重连说明，宿主断开但本机服务仍在时可回看已有剧情。
- 同一网页地址内切换任务。入口通过本机受限路由转发到所选的既有桥接服务，每次核对宿主与原任务身份。目录响应不包含桥接凭证或目标 URL；转发仅支持浏览器实际需要的操作，不转发发布剧情、关闭服务或任意地址。
- 草稿、播放进度、提交幂等、租约、配图与文档仍在各自的原任务中。刷新记住所选存档；CLI/MCP 发布绑定不随浏览器选择变化。切换不合并记忆或创建会话。
- 新入口可识别已经运行的旧桥接服务。旧入口必须重启才能启用同页切换；旧服务刷新页面时保留原来的跳转方式并说明升级限制。

## 已实测

### 自动验证

`npm test` 共 49 项通过，其中新增 8 项集成/单元检查：

1. 两个不同宿主、相同任务 ID、不同数据目录共用列表，凭证不进入目录响应。
2. 从 A 入口对 B 保存草稿、设置、发送与重复提交，只影响 B。
3. B 停止后条目仍可见；重启更新地址且不重复；删除网页记录保留原宿主消息。
4. 通过统一入口读取 B 的正式剧情图片和交付文档，内容与 B 一致。
5. 错误的宿主地址、伪造索引、外部地址与未授权操作被拒绝，未发生发送。
6. 旧版索引被新版登记及删除标记正确替代。
7. 并发索引写入仍是完整 JSON，损坏记录被跳过。
8. 默认目录不因 Agent 或安装工程不同而改变，显式隔离有效。

`npm run check`、`npm run build`、前端 JavaScript 语法检查与 Skill 校验通过。

### 浏览器实测

使用 `scripts/catalog-fixture.ts` 创建两个标为「无模型」的本机演示任务和一个断线条目：

- 列表同时展示两个宿主，筛选 WorkBuddy 后只显示对应条目。
- Codex 存档输入未发送草稿，切换到 WorkBuddy 后输入框为空；在 WorkBuddy 发送得到其自身演示回复；切回 Codex 时原草稿完整恢复。
- 全程浏览器地址未改变，立绘、台词、标题、宿主标识正确切换。
- 刷新后保留所选存档，恢复该存档的播放位置。
- 浏览器检查无脚本错误；这是确定性界面验证，不是新宿主兼容认证。

真实本机环境：升级当前 Codex 入口后，目录同时识别现有 Codex 和 WorkBuddy 原任务；在同一入口地址切换并读取 WorkBuddy 原对话，原有跨标签页租约仍生效。没有为本次检查向真实模型发送新消息，也未停止其他任务的桥接服务。公开记录不包含个人任务 ID、标题、聊天正文或令牌。

## 尚未验证与使用边界

- Claude Code 及其他尚无同步适配器的应用，不会因为安装 Skill 自动接入。
- macOS 只有公共路径实现，未在真实宿主实测；本次验证环境是 Windows。
- 没有做新的真实模型跨宿主发送回合；原宿主消息同步证据沿用各自已有报告，新增跨存档发送隔离由本机集成测试与浏览器夹具验证。
- 主入口桥接服务停止后该地址暂不可用，须从仍运行或重新启动的任一原任务打开入口。全部服务关闭时，没有独立的常驻后台网站。
- 服务完全停止的存档仍能看到名称与重连说明，但本版不提供离线剧情数据库浏览。不同系统账号和不同电脑不共用存档。

本机 Codex 与 WorkBuddy 的已安装 Skill 已更新；使用本功能需要运行新版入口，升级指南见仓库 GALGAME.md。
