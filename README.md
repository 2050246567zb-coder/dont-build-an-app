# 不要再做 App 了

**在开始开发之前，先把你的创意聊清楚。**

一个帮助你审查创意、理清产品设计、改善使用体验的 AI Skill。你可以只有一个模糊想法，通过分阶段对话，最终得到能交给 AI 开发的产品方案。自用工具、软件、硬件和内容创意都可以讨论。

## 直接发给你的 agent 安装

复制下面这段话，发送给支持安装本地 Skill 的 agent：

```text
请安装这个 GitHub 仓库里的 dont-build-an-app Skill：
https://github.com/2050246567zb-coder/dont-build-an-app

技能目录是 skills/dont-build-an-app。请阅读仓库的 INSTALL.md，
按当前 agent 的实际技能目录安装整个文件夹，保留 references、assets 和 agents。
安装完成后核对文件，并告诉我如何启用。
```

也可以直接把 [Skill 目录链接](https://github.com/2050246567zb-coder/dont-build-an-app/tree/main/skills/dont-build-an-app) 发给 agent，并说“帮我安装这个 Skill”。

需要手动安装或具体安装命令，请看 [INSTALL.md](INSTALL.md)。仅能聊天、没有本地文件或 Skill 安装能力的应用，无法仅凭一个链接完成永久安装。

## 安装之后怎么用

对 agent 说：

```text
使用“不要再做 App 了”审查我的创意：我想做一个……
```

支持按技能名调用的宿主也可以使用：

```text
$dont-build-an-app 我有一个产品创意：……
```

不用事先写完整需求，把你的想法、想解决的麻烦或大概的产品想象告诉它即可。

## 会经历什么

1. **同类与价值筛查**：搜索可访问的互联网，了解类似产品和有意义的区别，也认真对待自用价值。
2. **产品质询**：围绕目的、用户、核心体验和取舍深入追问，帮助你决定产品到底应该是什么。
3. **用户挑刺**：从实际使用情境出发，检查理解、操作、等待、犯错、中断、数据控制等关键体验。
4. **产品方案**：正常完成审查后，整理首版范围、流程与界面、功能、异常处理、数据规则、验收和开发任务。

角色有自己的判断，不会把每句“好”都当成设计已经完成。你可以求助，也可以明确把某些决定交给 AI；普通实现细节无需逐项回答。

## 结论图与可选回复配图

第一阶段聊清想法、形成建议后，会说“我的建议是：别做了”或“我的建议是：可以做”。支持生图时直接配一张结论图，无需另行确认：前者是掌心朝向画面、掌心写着“别做了”；后者是竖大拇指、大拇指正上方一个红色“中”字（无感叹号），正文仍说“我的建议是：可以做”。资料不足时会说明暂时无法判断，不强选结论。你可以随时要求全程纯文字。

进入角色阶段前会询问是否开启。当前 agent 同时支持生图和图片展示、且你同意后，通常每轮生成一张反应图，两位角色交接时各一张。表情与动作随对话变化，增强代入感。

结论图与人物配图都可能增加等待时间和生成额度或费用消耗；不支持或用户关闭对应配图时，继续纯文字。安装本 Skill 不会自动获得搜索、生图或其他工具能力，也不需要先安装 OpenCLI。

## 暂停与继续

说“今天先到这里”，它会询问是否把进度保存为文档。下次把进度文档交给 agent 并调用本 Skill，就可以核对后继续；不能只依赖不同应用的自动记忆。

## 最终能得到什么

正常完成后得到一份可执行产品设计方案，关键产品决定在前面阶段解决。实际效果需要验证的部分会成为开发中的验证任务；常规工程选择留有明确的 AI 裁量范围。

你也可以主动要求提前整理草案。此时会如实保留缺口，不伪装成已经通过审查。角色对话属于模拟预审，不能替代真实用户试用；搜索没有发现同类也不代表全网原创。
